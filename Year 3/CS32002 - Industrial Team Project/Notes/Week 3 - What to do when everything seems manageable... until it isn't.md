# Agile planning mindset
- Planning is continuous and adaptive
- Based on business value and priority
- Detail deferred to last responsible moment
- Only plan value-adding work
- Whole-team collaboration (no silos)
- Inspect and adapt via feedback & retrospectives
# PDCA cycle (Plan-Do-Check-Act)
### Plan
- High-level long term + detailed short term
- Just-in-time planning
### Do
- Build working increment
### Check
- Review results vs expectations
- Customer feedback
- Improve process
### Act
- Adjust plan
- Correct or prevent issues
- Continuous improvement
# Predictive vs adaptive planning
### Predictive
- Up-front detailed plan
- Baseline tracked
- Change controlled
### Adaptive
- Release plan + iteration plans
- Frequent replanning
- Respond smoothly to change
# Rolling wave planning
- Near work detailed
- Future work coarse
- Progressive elaboration
- Plan evolves as knowledge increases
# Cone of uncertainty
- Early estimates very inaccurate
- Accuracy improves over time
- Use ranges not precise values
Techniques to handle uncertainty
- Incremental delivery
- Frequent reviews
- Determine velocity
- Relative sizing
- Spikes
# Just-in-time planning
- Plan only when needed
- Avoid rework and waste
- Elaborate stories during iteration
# Timeboxing
- Fixed duration work period
- Scope adjusts, time does not
Examples
- Sprint: 2–4 weeks
- Stand-up: 15 min
- Planning: 8 hours
Benefits
- Focus
- Risk reduction
- Avoid Parkinson’s law
- Avoid Student syndrome
# Iterative & incremental delivery
- Build in small increments
- Each increment usable
- Frequent feedback
- Maximizes ROI
# Planning onion levels
### Strategy (years)
Vision and direction
### Portfolio (years)
Products to achieve vision
### Product (months–years)
Roadmap and charter
### Release (months)
Features grouped
### Iteration (weeks)
Stories selected
### Daily (day)
Stand-up coordination
# Iteration planning
- PO presents prioritized backlog
- Team clarifies stories
- Break into tasks
- Estimate and commit based on velocity
May consider
- Capacity
- Risk
- Defects
- Absences
Anti-patterns
- Sprint zero
- Hardening sprint
# Choosing iteration length
Shorter iterations when
- High uncertainty
- Frequent releases
- Rapid priority change
Longer iterations when
- Stable requirements
- High ceremony overhead
Typical optimal: 2–3 weeks
# Agile estimation purpose
- Determine feasibility and ROI
- Guide release and iteration planning
# Relative sizing
- Compare to baseline
- Not absolute time
# T-shirt sizing
- XS S M L XL XXL
- Quick coarse estimates
# Ideal time
- Time with no interruptions
- Ignores meetings and overhead
# Story points
- Relative complexity measure
- Not tied to hours
- Project-specific scale
Advantages over ideal time
- Independent of developer skill
- Faster estimation
- Encourages cross-functional thinking
# Estimation techniques
## Affinity estimation
- Group similar stories
- Fast large backlog estimation
## Wideband Delphi
- Anonymous expert consensus
- Multiple rounds until converge
## Planning poker
- Fibonacci cards
- Discuss outliers
- Repeat until agreement
# Velocity
- Story points completed per iteration
- Only done stories count
Uses
- Sprint planning
- Forecast delivery
- Track progress
# Improving velocity
- Refactor code
- Reduce distractions
- Collaborate with customer
- Improve team motivation
# Forecasting schedule & cost
Steps
1. Estimate backlog story points
2. Determine velocity
3. Iterations = backlog ÷ velocity
4. Time = iterations × iteration length
5. Cost = iteration burn rate × iterations
Used for ROI decisions
