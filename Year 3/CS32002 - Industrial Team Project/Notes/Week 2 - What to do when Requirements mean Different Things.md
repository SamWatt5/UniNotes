# User stories  
- Fundamental Agile requirement description  
- Written from the user perspective  
- Captures:  
- Who (role)  
- What (goal)  
- Why (benefit)  
- Used to trigger conversation, estimation, design and testing  
- Can represent:  
- Feature  
- Enhancement  
- Technical task  
- Defect  
# User story format  
### Role–Feature–Reason  
As a <role> I want <goal> so that <benefit>  
### Given–When–Then (BDD / ATDD)  
Given <context>  
When <action>  
Then <outcome>  
# 3 C’s of User Stories  
### Card  
- Short reminder of requirement  
- Barely sufficient documentation  
### Conversation  
- Discussion clarifies details  
- Happens during planning & development  
### Confirmation  
- Acceptance tests verify correctness  
# Hierarchy  
### Epic  
- Large story spanning iterations  
- Used for release planning  
- Broken into stories  
### Feature  
- High-level functionality  
- Also decomposed into stories  
### Theme  
- Related stories grouped for planning  
### Story  
- Unit of estimation & implementation  
### Task / Subtask  
- Technical implementation work  
### Value-based decomposition  
Epic → Feature → Story → Task  
# INVEST qualities  
### Independent  
- Not dependent on other stories  
### Negotiable  
- Not a contract  
- Can change  
### Valuable  
- Provides customer value  
### Estimable  
- Can be sized  
- Spike if unknown  
### Small  
- Fits iteration  
### Testable  
- Clear acceptance criteria  
# SMART stories  
### Specific  
Clear purpose  
### Measurable  
Definition of done verifiable  
### Achievable  
Can be completed in iteration  
### Relevant  
Provides value  
### Time-boxed  
Fits sprint duration

# Best practices  
- Use proxies if customer unavailable  
- Slice vertically (end-to-end value)  
- Build tracer bullet functionality  
- Closed stories (clear goal)  
- Write for one user  
- Active voice  
- Simple language  
- Defer UI details  
- Smaller than use cases  
- Stored in product backlog (PBI)  
# Backlog flow  
Product backlog → Prioritized → Sprint backlog → Increment
