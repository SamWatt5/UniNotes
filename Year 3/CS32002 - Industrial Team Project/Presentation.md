After reading the brief, we decided on personas for the system so that we could understand who would be using the system, and how they would want the system to work.  After defining these personas, we used them to create user stories. These user stories were used to create a list of requirements for the system. Having this high-level start helped us in the long run due to everyone understanding exactly the system we were building, and removing doubt about how different parts of the system were to work. 
During the actual development we decided to follow an agile approach, having short daily standups, discussing what we worked on individually the day before, what we were going to work on that day, and what blockers we were facing, slowing down development. We did this so that everyone was on the same page throughout the process.
